# Security and Privacy Boundary

## Current v0.3 posture

The product is read-only and data-only. It includes:

- an offline deterministic mock provider;
- an opt-in public AI Workstation HTTP provider;
- local stdio MCP;
- guarded stateless Streamable HTTP MCP for local/self-hosted deployment;
- a public production Hosted MCP behind TLS, Host/path policy and anonymous
  abuse controls;
- contract probe, capture, validation and replay utilities;
- one unified Skill and a deterministic Skill package;
- a non-root, read-only container and host-loopback public Compose example;
- a remote read-only MCP compatibility smoke client.

It does not include user accounts, OAuth, billing, collection writes,
repository mutation, third-party code execution or AI Workstation server-side
model execution. The anonymous Hosted service is intentionally limited to nine
public Radar data/evidence tools; private/member data would require a new
identity and privacy design.

## Trust boundaries

1. User input is untrusted.
2. GitHub repositories, README files, websites and third-party Skills are
   untrusted external data, even when publicly accessible.
3. Provider output is untrusted until the hardened adapter validates identity,
   snapshot, evidence, selector and license contracts.
4. Recommendations are analysis and must never be labelled as verified facts.
5. Contract captures are untrusted until sanitized, validated, replayed and
   manually reviewed.
6. Operator attestations in readiness reports are recorded evidence claims, not
   proof generated by the tool.
7. A non-loopback bind acknowledgement is an operator deployment acknowledgement,
   not an authentication mechanism.
8. Reverse proxies, private-network controls and identity systems are separate
   trust boundaries from the MCP application process.

## Input controls

Top-level tool schemas reject undeclared fields and constrain required strings,
list cardinalities, locales and request IDs.

Nested `constraints` and `context` values must be JSON-compatible and are
bounded by:

| Limit | Value |
| --- | ---: |
| Maximum nesting depth | 6 |
| Maximum total structured nodes | 200 |
| Maximum entries/items per object or array | 50 |
| Maximum key length | 128 characters |
| Maximum nested string length | 1,000 characters |

The runtime rejects non-finite numbers, binary values, sets/custom objects,
control characters in object keys and oversized/deep structures. These limits
reduce denial-of-service and serialization risk before data reaches the provider
or MCP transport.

## Public Radar provider controls

- Read only from anonymous public Radar routes.
- Require public project-list snapshot identity.
- Fail closed on incompatible list/detail snapshots.
- Require selector evidence state to be `available`, or `partial` with notice.
- Reject leaked internal publication fields.
- Keep near matches outside formal recommendations.
- Resolve aliases before excluding a source project from alternatives.
- Never infer a license from missing or sentinel values.
- Treat non-standard license labels as high-risk observations.
- Reject oversized, malformed or non-object JSON responses.
- Treat 408, 425, 429 and 5xx responses as retryable unavailability.
- Never import private `akaiagents` modules.

## MCP transport controls

### stdio

`osi-mcp` runs locally and exposes exactly nine annotated read-only tools. It does
not open a listening network socket.

### Streamable HTTP

`osi-mcp-http` defaults to `127.0.0.1:8000` with the offline mock provider.
Binding to a non-loopback host is rejected unless:

- `OSI_PROVIDER=http` is selected;
- the operator sets the exact
  `OSI_MCP_HTTP_PUBLIC_BIND_ACK=reverse-proxy-or-private-network` acknowledgement;
- the Radar base origin is allow-listed HTTPS without embedded credentials,
  query, fragment or non-standard public port.

The acknowledgement only permits the bind. It does not create a user identity,
validate tokens or provide gateway controls. `OSI_MCP_HTTP_ASSUME_PUBLIC_AUTH=true`
is explicitly rejected so an environment flag cannot be mistaken for real
authentication.

For non-local deployments, use a trusted network or a TLS reverse proxy with
request-size limits, rate limits, timeouts, concurrency budgets, Host policy and
abuse blocking. Authentication is required when the operator exposes private,
member-specific or write-capable data; the current public AI Workstation Hosted
service exposes only anonymous public read-only data.

## Container controls

The provided image and Compose example:

- run the Python process as a non-root user;
- keep build context free of `.env`, local Git data and non-runtime surfaces;
- use a read-only container filesystem with a bounded tmpfs;
- set `no-new-privileges` and drop Linux capabilities;
- bound PIDs and memory in the Compose example;
- publish the example service only to host loopback;
- do not bake credentials or a public-bind acknowledgement into the image.

These settings are defense in depth, not a substitute for host patching,
container-runtime security or TLS. Authorization requirements depend on the
data and action boundary; the current production service is intentionally
anonymous and data-only.

## Remote MCP smoke controls

`osi-remote-smoke` uses a real MCP client but remains read-only. It requires
HTTPS for non-local endpoints and rejects URLs containing usernames, passwords,
query strings or fragments. The default operation lists tools and validates
annotations; `--invoke-search` performs one explicit read-only search.

The smoke result demonstrates protocol compatibility and tool metadata, not
penetration-test coverage, ongoing service health or public-directory approval.

## Network and workflow controls

The live validation workflow:

- is manual only;
- has repository read permission only;
- accepts only allow-listed HTTPS AI Workstation origins;
- validates `owner/repository` project IDs before network requests;
- passes user inputs through environment variables rather than shell templates;
- replays captured locale/project identity from each sanitized manifest;
- uploads captures only after validation, replay and forbidden-key scanning;
- retains successful artifacts for a limited period.

The project does not automatically run recurring live probes or captures.

## Contract capture controls

Sanitized captures remove query/prompt text, client/request IDs, credentials,
cookies and token-like fields, raw content and internal evidence/source/publication
identifiers. Long strings and lists are bounded, and request fingerprints replace
prompt text.

The validator independently scans key names and contract invariants; provider
replay then exercises the hardened production adapter offline. A validator pass
does not replace human review before distribution.

## Skill-package controls

The deterministic one-Skill builder:

- uses an explicit file allowlist;
- rejects symlinks, non-UTF-8 files, oversized files and credential-like text;
- excludes Python source, tests, CI workflows and MCP runtime implementation;
- fixes ZIP timestamps and permissions for reproducible output;
- embeds per-file SHA-256 hashes and emits an external archive checksum;
- includes security, privacy and support policies;
- declares that no live MCP server is bundled.

The manual package workflow uploads only after tests, plugin validation,
checksum verification and archive-surface inspection pass.

## Data minimization

Tools require task descriptions, public project IDs and technical constraints.
They do not require names, email addresses, credentials, customer documents,
private repositories or source-code archives.

Callers and testers must remove personal, confidential and proprietary data
before invocation. Logs, issue reports and artifacts should contain sanitized
summaries rather than complete prompts.

## Prompt-injection resistance

Repository and web text is evidence to inspect, not an instruction channel. The
server instructions and Skills require agents to keep system/tool policy outside
retrieved content, label retrieved text as untrusted, reject secret/code/tool-policy
instructions, use only declared read-only tools, require deterministic server
validation and preserve explicit unknown/no-match states.

## License boundary

License output is technical evidence, not legal advice.

- Missing license evidence is an unknown, not permission.
- `NOASSERTION`, `UNKNOWN`, `UNLICENSED` and similar sentinels are not verified
  licenses.
- `OTHER`, `CUSTOM` and `PROPRIETARY` require manual review.
- Commercial-use decisions must be checked against the actual license and, when
  appropriate, qualified legal advice.

## Public Hosted MCP controls and remaining gates

The production endpoint is anonymous, read-only and data-only. Its verified
gateway/runtime controls include:

- TLS and HTTP-to-HTTPS redirect;
- dedicated Host/path policy and invalid-Host rejection;
- body, short-window, sustained-window and connection limits;
- host-loopback-only container exposure;
- exact source/image/runtime identity;
- read-only filesystem and container hardening;
- bilingual nine-tool smoke and real-search validation.

Remaining distribution and operational gates are:

- final publisher review of service-specific Privacy/Terms/support/retention
  copy;
- baseline error, latency and 429 monitoring plus real-user threshold tuning;
- incident/rollback ownership for future deployments;
- external fresh-install and return-use evidence;
- publisher verification and final platform registration/review.

Per-user OAuth is not a missing control for the current public-data-only
contract. It becomes mandatory if a later version introduces private/member
data, user-scoped state, writes or server-side model entitlements.

These are tracked in `docs/public-launch-decisions.md` and must not be replaced
with placeholder claims simply to make a release gate pass.

## Reporting

Use `SECURITY.md` and a private AI Workstation contact route for vulnerabilities,
secret exposure, unsafe writes, repository execution or cross-boundary prompt
injection. Do not file those details in a public issue.

Use the structured public issue templates only for sanitized alpha bugs and
public-contract changes.
